# 口袋蕾姆 2.0 使用与升级说明

当前版本为 2.0.2，包含大量任务时的切页优化，并将设置页的“关于口袋蕾姆”置顶、“连接配置”移至底部。继续使用原签名身份覆盖安装，先保持只读，连接 qB/TR 并等待任务载入后，在五页之间往返、搜索一份任务并切换筛选，再核对分组、断开与重连。原有背景、海报、只读锁和迁移保护均保留。实际测试范围与结果见随版本提供的构建验证说明。

本版发布于项目 GitHub Releases。旧版 1.3.0、2.0.x 与本版为同一 Bundle ID，使用原有签名身份覆盖安装可保留本机配置；变更签名组、卸载应用或清理沙盒可能影响配置和钥匙串访问。升级前保留自己原有的连接备份，不要上传账号文件。

## 添加与断开

在“设置 → 服务器设置”添加服务器，选 qBittorrent 或 Transmission 后填写自定义名、完整地址与账号。下载器可添加多台；MP 和旧 Emby 各保留一个。公网入口使用有效 HTTPS，内网入口需同一网络或自己的 VPN。

保存连接默认保持全局只读。单台管理授权、全局只读与迁移保护是独立开关。旧版家庭 qB1/TR 的身份、权限和迁移标记保持；只剩钥匙串而没有原地址的恢复条目保持断开，先编辑真实地址再点连接。

同一编辑页提供四种不同操作：

| 操作 | 账号凭据 | 本机条目 | 远端任务 |
| --- | --- | --- | --- |
| 断开连接 | 保留 | 保留并停用 | 继续运行 |
| 连接 | 复用 | 启用读取 | 不启停、不修改 |
| 清理凭据 | 删除 | 保留，管理权限关闭 | 不修改 |
| 移除服务器 | 删除 | 移除并清分类关联 | 不修改 |

改名不影响凭据、分类、权限或 MP 对应关系。更换服务器地址、删除条目后，旧的 MP 对应关系需要重新确认。两个下载器条目不能填写同一入口，以免重复统计。

## 分组与状态表

在“设置 → 服务器分组”建立家庭、刷流等分组，勾选所需下载器。状态表与下载器页面共用统计范围。选择全部服务器后每个实例只算一次，即使它同时在多个分组内。

切换分组会读取新范围，关闭自动刷新时也会执行首次读取；同范围同时刷新会合并。独立下载器访问最多四路并发。离线成员保留部分覆盖提示，失败不等于零任务。磁盘余量按目录逐项展示，不累加可能共享的 NAS 空间。

删除分组只改本机分类，服务器与任务保留。断开连接的实例仍留在设置和分组中，但不继续轮询或参与当前流量合计。

## MP 使用

“发现 → 影视”对应自己 MP 的推荐，搜索作品后可按 MP 既有规则订阅。影视海报由当前 MP 的认证图片缓存读取，失败可手动重试。

“发现 → PT资源”先选站点再搜索，进入具体资源后选 MP 下载器及目录。第一次实际下载前，在设置中确认 MP 内部下载器与 App 的哪一台实际服务器相同。MP 容器地址和手机地址可以不同，不能只凭显示名推断。

本机预设目录只从 MP 已配置目录选择，默认不覆盖 MP 自己的默认规则。每次实际订阅、下载、启停或限速仍需权限和确认；结果不明的提交不自动重发。本人发布与校验任务保护保持。

## 本地导入与恢复

旧 v1 文件仍可用。新 [v2 模板](../examples/connection.v2.example.dkmp) 用 `type` 区分协议、`name` 命名；相同协议可以出现多次，App 为新条目产生独立身份。也可用导出的稳定 `kind` 更新已有实例，不能把其协议改成另一种。导入逐项预验后再保存，管理权限默认关闭。

配置损坏不会自动退回旧槽位或清空。用户主动导入有效备份时，会先把损坏原配置留存本机再恢复；恢复文件中包含哪些服务器，就恢复哪些服务器。原有待核对业务提交记录不清除。

## 两台手机复测

建议先保持只读，依次验证：覆盖安装后旧连接可读；添加两台同协议下载器互不混淆；家庭/刷流/全部切换；关闭自动刷新后切组；断开再连接无需重填密码；删除一个分组不影响服务器；发现海报、站点搜索、订阅列表；浅色/深色、中英及字体；外出 VPN。

本版不自动向手机安装、配对、开启开发者模式或调整证书。USB 识别系统版本不代表 App 界面或业务已通过实机测试。真实管理写入留待用户自行确认测试；自动化验证使用模拟器与合成接口；iPhone 17 Pro Max 用户已确认 2.0.1 的切页卡顿改善。
